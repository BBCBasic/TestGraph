# Contributing to TestGraph

TestGraph welcomes bug reports, design discussion and, when explicitly accepted, code contributions.

## Licence model

The public TestGraph codebase is licensed under the GNU Affero General Public License v3.0 (`AGPL-3.0`). The project owner may also offer the same code under separate commercial or proprietary terms.

To preserve that dual-licensing option, code contributions cannot be accepted on AGPL-only terms.

## Contributor licence grant

By intentionally submitting a code contribution for inclusion in TestGraph, you represent that you have the right to submit it and you grant the TestGraph project owner a perpetual, worldwide, non-exclusive, irrevocable, royalty-free copyright licence to use, reproduce, modify, prepare derivative works from, distribute, publicly perform, publicly display, sublicense and relicense that contribution, including under licences different from AGPL-3.0 and under commercial or proprietary terms.

You retain ownership of your contribution. This grant does not transfer your copyright; it gives the project owner the additional rights needed to continue offering alternative licences for TestGraph.

If you are contributing on behalf of an employer or another organisation, you must have authority to make this grant for the contribution.

If you cannot make this grant, do not submit code for inclusion without first contacting `testgraph@21dle.co.uk` to agree different terms in writing.

## Pull requests

Before opening a pull request:

1. Keep the change focused and explain the problem it solves.
2. Add or update tests for behaviour changes.
3. Do not include credentials, personal data, production exports or third-party material unless its redistribution rights are clear.
4. State any external source, dataset or generated material used in the change and its licence/provenance.
5. Confirm in the pull-request description that you have read and agree to the Contributor licence grant above.

The project may require a separate signed contributor agreement for substantial, corporate or legally complex contributions.

## Security issues

Do not open a public issue for an unpatched vulnerability or exposed credential. Follow `SECURITY.md` instead.
